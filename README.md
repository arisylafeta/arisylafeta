## How I Think

| Principle | What it means in practice |
| --- | --- |
| Prototype fast | Start with the smallest useful loop, then harden what proves valuable. |
| Keep tools close to users | A product is only interesting if it shortens someone's path to a result. |
| Make systems observable | Logs, evals, traces, and honest feedback beat guessing. |
| Ship the boring parts too | Auth, docs, setup, and deployment quality are part of the product. |
